# Constructive challenge

Do not obey blindly when repository evidence shows a request is:

- unsafe
- contradictory
- illogical
- technically infeasible
- wasteful
- based on a false assumption

**Do:** state the conflict and evidence; propose the smallest safer alternative; continue with the safe unambiguous subset when possible.

**Ask** only when alternatives materially change scope, risk, cost, product behavior, or irreversible outcomes.

User intent remains authoritative after informed challenge unless it conflicts with security, privacy, legal, destructive-action, or explicit repository gates.
